# Kite daily-history capture contract — 6 September 2026

The user has a Kite API key and 500 credits and has authorized efficient bulk stock-data acquisition. Capture is a read-only data operation. Credits, account ownership and an API key do not themselves prove that the paid data app is active; the first authenticated data response must establish access. This research used no credentials or authenticated requests.

## Request limits and cost

The current official API documentation permits **3 historical-candle requests per second**. Use a shared limiter at **2 requests per second**, with bounded backoff for 429/5xx errors and resumable checkpoints. These conservative implementation choices leave headroom; they do not change the provider's limit. [Official rate-limit documentation](https://kite.trade/docs/connect/v3/exceptions/#api-rate-limit).

Kite staff specify **2,000 calendar days per daily request** in the official forum's interval table, edited May 2020. A June 2024 retention discussion again records the 2,000-day server limit. No primary source for a 600-day daily limit was found. The current core endpoint documentation does not itself publish this span table, so capture should retain actual server errors if the rule has changed. Use at most **1,999 days between endpoints**, representing 2,000 inclusive calendar dates, to avoid boundary ambiguity. [Staff interval table](https://kite.trade/forum/discussion/3105/historical-api-frequency-and-limit-on-number-of-candles-fetched), [2024 retention discussion](https://kite.trade/forum/discussion/14149/historical-data-retention-policy).

The current plan is **₹500 per month per API key** for live and historical data. This is subscription access, **not a budget of 500 historical requests**. Legacy staff documentation describes credits being applied to a 30-day app subscription; its old ₹2,000 price is superseded. Verify the actual app expiry in the developer console rather than assuming a new 30-day period starts with this download. API-session token expiry is separate from subscription validity. [Current Zerodha pricing](https://support.zerodha.com/category/trading-and-markets/general-kite/kite-api/articles/historical-data-and-live-market-data-payment-plan), [Legacy credit-cycle explanation](https://kite.trade/forum/discussion/2540/how-to-make-automation-of-trading-with-python-and-kite-connect-api).

## Frozen acquisition scope

Recommended scope: **1996-01-01 through 2026-09-04**, daily candles, for the frozen current NSE cash candidate master, followed by explicitly recorded historical-symbol exceptions. This yields six 2,000-date windows per instrument. A start at 2000 would use five windows but could miss supported late-1990s data. Staff explicitly say there is no fixed earliest daily date and that some NSE stocks were backfilled into the late 1990s. Do not promise history from inception for every symbol. [Official retention clarification](https://kite.trade/forum/discussion/14149/historical-data-retention-policy).

Use `GET /instruments/historical/{instrument_token}/day`, with explicit date bounds and `continuous=0`. Continuous history is for supported futures, not cash-equity symbol lineage. Preserve each original response, request window, instrument token, symbol, master hash, retrieval time, response status and content hash. Keep empty windows as evidence of unavailable data, not zero-price bars. Merge only exact, consistent overlaps; conflicting overlaps must be reported. [Historical API contract](https://kite.trade/docs/connect/v3/historical/).

For N candidates the nominal upper plan is approximately **6 × N history requests**, plus bounded probes/retries. At 2 requests per second, request pacing alone is about **3 × N seconds**; network latency and retries add time. This estimate is not a completion guarantee. Resume verified completed windows instead of paying the time cost of downloading them again.

The instrument master is a present-day inventory. `exchange=NSE` plus `instrument_type=EQ` is a candidate filter, not a verified common-stock classifier: it can include ETFs and other cash instruments. Join to official NSE security classification/ISIN evidence before calling the resulting dataset “all stocks”; retain exclusions with reasons. [Kite instrument schema](https://kite.trade/docs/connect/v3/market-quotes/), [Official forum discussion of EQ filtering](https://kite.trade/forum/discussion/15313/get-only-stocks-not-etfs-and-any-other-instruments).

Current-master capture does not recover a complete historical universe. Kite staff state that it is not a comprehensive data-vendor offering for retired/unlisted instruments. Compare raw NSE historical symbol/ISIN coverage against the captured master and record unmatched former members separately; never silently remove them from a backtest or treat today's stock list as historical membership. [Staff survivorship-bias response](https://kite.trade/forum/discussion/15119/survivorship-bias-free-historical-equity-data).

## Adjustment semantics and acceptance boundary

Label returned prices **Kite corporate-action-adjusted**, not raw exchange prices and not automatically total-return prices. Current Zerodha support describes bonuses, splits, rights issues, spin-offs and extraordinary dividends of at least 2% of market value. Demergers/spin-offs use company Cost of Acquisition information. This differs from a blanket promise to reinvest all ordinary cash dividends. [Current adjustment explanation](https://support.zerodha.com/category/trading-and-markets/charts-and-orders/charts/articles/kite-charts-not-matching-as-per-the-records-in-nse-or-bse).

2026 staff responses say relevant historical volume is adjusted for bonuses, splits, rights and demergers, but not dividends; they also say no dedicated corporate-actions API is offered. Another staff response notes demergers wait for the COA file. Thus historical values can be revised, and a download is a timestamped provider vintage. Older forum answers loosely say dividends are adjusted; do not use that phrasing to claim full dividend-total-return semantics. [Price/volume and action-API clarification](https://kite.trade/forum/discussion/15971/getting-the-right-closing-prices-adjusted-for-corporate-actions), [Adjustment timing and COA exception](https://kite.trade/forum/discussion/16099/split-adjustment-data).

Before promoting the new snapshot, test the four known missing sessions (2024-01-20, 2024-03-02, 2024-05-18 and 2026-02-01), the four verified holiday exclusions, BSE's 2025 bonus, TCS dividends and ITC's demerger against retained raw NSE evidence. Bulk acquisition can proceed into quarantine; completeness, corporate-action certification and point-in-time membership remain separate verdicts. Do not overwrite the existing Yahoo series or splice Kite-adjusted values into it without proving a compatible adjustment convention.
